# AI Tool Usage Report — mini-research-claw

## Overview

This document records how AI tools were used throughout the development of the autonomous ML research pipeline. It covers every phase from initial architecture design to CI/CD setup, including what was generated, how it was validated, and what was learned.

**Primary tools used:**
- **Claude (Anthropic)** — architecture design, code implementation, test writing, bug diagnosis, CI/CD, documentation
- **GitHub Copilot** — inline code completion, boilerplate, commit messages

---

## 11.1 Usage by Development Phase

### User Stories & Product Backlog

**Tool:** Claude (claude-sonnet-4-6)

**How it was used:** Generated the initial set of user stories from the project description. Refined acceptance criteria through back-and-forth prompting until each story was specific and testable.

**Validation:** Each story was reviewed manually and adjusted to match the actual scope of the pipeline. Roughly 20% were rewritten or merged.

**Reflection:** Effective for bootstrapping a large backlog quickly. Less effective at estimating story complexity — those estimates were done manually.

---

### Architecture & Design Overhauls

**Tool:** Claude (claude-sonnet-4-6)

**How it was used:** The initial architecture went through 9 major overhauls based on a peer review. Claude was used to analyze the review feedback and propose concrete implementation changes for each:
- KG polarity (`supports` / `contradicts` edges)
- Iterative ArXiv retrieval (hypothesis-driven, up to 3 rounds)
- Prior-art screening with pgvector
- Double HITL gates (hypothesis + experiment)
- Claim ledger with `context_condition`-aware evidence rating
- No-Paper outcome gate
- Deterministic linter before the review panel
- Scoped state views (`build_scoped_view`) to prevent token bloat
- Supabase cloud integration (paper caching, artifact storage, run tracking)

**Validation:** Each proposed change was evaluated against the peer review criteria before implementation. Several suggestions were rejected when they introduced unnecessary complexity.

**Reflection:** Claude was most useful here as a sounding board — generating multiple implementation options and explaining trade-offs. Final architectural decisions were always made by the developer.

---

### Code Implementation

**Tools:** Claude (claude-sonnet-4-6), GitHub Copilot

**How it was used:**
- Claude generated full agent implementations (prompt templates, LLM call logic, state updates) for all 14 pipeline nodes
- Copilot completed repetitive boilerplate (imports, type hints, dict lookups)
- Docker configuration (`Dockerfile.sandbox`) was generated by Claude from a description of sandbox requirements

**Validation:** Every generated function was reviewed line-by-line before committing. All 14 nodes were tested with unit tests before integration.

**Reflection:** Claude was faster than Copilot for complex multi-step logic (e.g., the claim ledger builder's `context_condition`-aware rating). Copilot was faster for short, repetitive completions.

---

### Test Writing

**Tools:** Claude (claude-sonnet-4-6), GitHub Copilot

**How it was used:** Claude generated the full pytest test suites for all 14 nodes — unit tests, integration tests, and eval scaffolding. Mock fixtures and patch decorators were generated from function signatures.

**Output:** 316 unit and integration tests across 22 test files, plus 12 agent evals.

**Validation:** Tests were run locally before committing. Several generated tests were incorrect (wrong mock setup, wrong assertion) and were fixed manually. Approximately 15% required non-trivial edits.

**Reflection:** Claude was effective at generating test structure but occasionally produced tests that passed trivially (e.g., asserting `result is not None`). Those were strengthened with specific value assertions.

---

### Agent Eval Design

**Tool:** Claude (claude-sonnet-4-6)

**How it was used:** Designed evaluation rubrics and LLM-as-judge prompts for 12 agent evals. Each eval uses Claude Haiku as a judge scoring outputs on a 1–5 scale with a defined threshold.

**Validation:** Rubrics were reviewed to ensure the scoring criteria matched the intended behavior. Pass thresholds were set conservatively (≥ 3.0/5) to avoid false negatives.

**Reflection:** The LLM-as-judge pattern worked well for subjective quality checks (e.g., hypothesis coherence, revision improvement). Less reliable for factual correctness — those were checked with deterministic assertions instead.

---

### Bug Diagnosis & Resolution

**Tool:** Claude (claude-sonnet-4-6)

**How it was used:** Three bugs were identified, diagnosed, and fixed with Claude assistance:
- **BUG-001** — `requires-python` had no upper bound; PyTorch has no wheels for Python 3.14. Fixed by adding `<3.14` constraint to `pyproject.toml`.
- **BUG-002** — `academic_writer` crashed when the LLM returned raw LaTeX instead of a JSON envelope. Fixed with try/except fallback.
- **BUG-003** — `hypothesis_generator` crashed on malformed LLM response (missing `hypothesis` key). Fixed with try/except fallback.

Each bug was filed as a GitHub Issue, fixed on a dedicated branch, and merged via PR.

**Reflection:** Claude was accurate at diagnosing root causes from code snippets. All three root-cause analyses were correct on the first attempt.

---

### CI/CD Setup

**Tools:** Claude (claude-sonnet-4-6), GitHub Copilot

**How it was used:** Generated `.github/workflows/ci.yml` (lint, type check, unit tests, Docker build) and `.github/workflows/cd.yml` (build, package, GitHub Release) from a plain-text description of requirements.

**Validation:** Workflows were tested by opening PRs and observing GitHub Actions output. Several ruff rules were configured to ignore false positives that don't affect runtime behavior.

**Reflection:** The generated YAML was correct in structure but required iterative adjustment to pass CI (ruff ignore rules, mypy configuration). Two round-trips were needed before all jobs went green.

---

### Documentation

**Tool:** Claude (claude-sonnet-4-6)

**How it was used:** Drafted the implementation plan (`Mini_Research_Claw_Full_Plan.md`), the implementation guide (`docs/IMPLEMENTATION_GUIDE.md`), and this report.

**Validation:** All documentation was reviewed and edited for accuracy against the actual codebase.

**Reflection:** Claude produced well-structured documentation quickly. The main editing needed was correcting details that didn't match the final implementation (e.g., node counts, threshold values).

## 11.4 Reflection

AI tools accelerated every phase of this project. The biggest gains were in:
1. **Test generation** — writing 316 tests manually would have taken significantly longer
2. **Architecture refinement** — using Claude as a sounding board for the 9 design overhauls
3. **Bug diagnosis** — all three root causes identified correctly on the first attempt

The areas where AI added less value or required more oversight:
1. **Eval rubric calibration** — thresholds and scoring criteria needed manual judgment
2. **CI/CD iteration** — required back-and-forth to match the existing codebase style
3. **Type annotations** — mypy errors in TypedDict/LangGraph code required human understanding to decide what to ignore vs. fix
